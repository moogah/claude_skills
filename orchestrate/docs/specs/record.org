* Purpose

The record is where a change's process is kept in the home: the change's own directory, its state,
and the journal of short narrative. Other capabilities state that something is recorded ("the
change's record shows the regression against the task", "the change's journal records the cause");
this spec states where and in what form, so that what they record can be found and read.

This draft covers only what =execute= and =asks= name. Not yet extracted: the gates and their
checks, the counts, the cycle archive, the handshake, the agent entries, migration and recovery.

* Requirements

** Requirement: A change has a directory of its own in the home
:PROPERTIES:
:GOAL:     none stated
:END:
Each open change SHALL have one directory in the home, named for the change, holding its process
files. The home's git SHALL track that directory, except the output of test runs and the tool's
own temporary files.

*** Scenario: The change's directory is named for the change, under the home
- *WHEN* a change is open
- *THEN* its process files are in =.orchestrator/changes/<change>/= under the home
- *AND* that directory holds the change's state, its cycles, its inbox of asks, its handshakes and its test runs

*** Scenario: The change's directory is tracked by the home, its test runs are not
- *WHEN* the home's git is asked what it tracks under =.orchestrator/=
- *THEN* it tracks the change's directory
- *AND* it ignores the test runs' output, the tool's temporary and lock files and its migration backups

** Requirement: The change's state is written only through the state tool
:PROPERTIES:
:GOAL:     none stated
:END:
The change's state SHALL be one file in the change's directory, written only through the state
tool's commands, which refuse what does not fit its form.

*** Scenario: The state is one file of the change's directory
- *WHEN* a cycle of a change is open
- *THEN* the change's state is the file =state.json= in the change's directory

*** Scenario: No role edits the state file by hand
- *WHEN* any role changes the change's state
- *THEN* it does so through a state tool command
- *AND* never by writing the file with an editor, a heredoc or a text filter

** Requirement: A fact about a task is recorded on the task's entry
:PROPERTIES:
:GOAL:     none stated
:END:
The change's state SHALL hold one entry per task of the cycle, and a fact found about a task SHALL
be recorded on that task's entry, with the evidence it rests on where it has one.

*** Scenario: A regression is marked on the task's entry, with the run that shows it
- *WHEN* a merge causes a regression
- *THEN* in the state file, the entry of the task whose merge caused it has =regression_detected= true
- *AND* its =after_snapshot= names the file holding the test run after that merge

** Requirement: The journal holds short narrative, each line against what it concerns
:PROPERTIES:
:GOAL:     none stated
:END:
The change's state SHALL hold a journal: one entry per piece of short narrative that has no other
home (a discovery, a decision, an inline fix, a deviation from the flow, a push-back, a note), each
naming its kind and what it concerns, in one line, with any longer form in a file.

*** Scenario: A journal entry names its kind and what it is against
- *WHEN* a role records a discovery, a decision, an inline fix, a deviation, a push-back or a note
- *THEN* the state file's =journal= gains one entry whose =kind= is that kind, whose =text= is one line and whose =at= is the time
- *AND* its =ref= names the task, finding, ask or seam it is against, when it is against one

*** Scenario: A journal line is short, and the long form is a file
- *WHEN* what a role has to record runs longer than one line
- *THEN* the journal entry's =text= is at most 280 characters
- *AND* its =path= names the file that holds the rest

** Requirement: The state file's shape is the record's boundary
:PROPERTIES:
:GOAL:     none stated
:END:
What another role, or an eval, may rely on in the record SHALL be the state file and the fields this
spec names: the change's directory, =state.json=, a task's entry by its =task_name= with its
=regression_detected= and =after_snapshot=, and the =journal= with each entry's =kind=, =ref=, =text=,
=at= and =path=. The rest of the file is the state tool's own. A tool that changes a named field
changes this spec.

*** Scenario: A reader finds a task's facts by the fields the record names
- *WHEN* a reader outside the state tool needs to know whether a regression was recorded against a task, or what the journal holds against it
- *THEN* it reads the change's =state.json= and finds them in the fields this spec names
- *AND* it needs nothing else of the file's shape

#+TITLE: Glossary
#+OPTIONS: ^:{} -:nil

The orchestrate skill's agreed terms. The eleven below were agreed during the research effort =~/emacs-workspaces/claude-skills/research/skill-evals/= (2026-11-11). The =state-layer= branch adds this file too, with its own terms; when the two meet, the file holds both sets.

* outcome
Something =orchestrate= is supposed to result in that the user would notice without reading the skill text.
- Example :: "It would be better to establish a list of behaviors the orchestrate skill is supposed to result in, and have evals for those."
- Avoid :: goal (the north star's word, for a whole change or many), requirement, behaviour (used loosely for both an outcome and a rule)
- Specs :: skill-evals

* rule
An instruction in a flow or role doc that an agent must follow; how the skill produces an outcome.
- Example :: a hand-back is one line of at most 200 characters.
- Avoid :: behaviour
- Specs :: skill-evals

* interface artifact
A file one step of the skill writes and another step, usually of a different role, reads as its input; the place where work passes between agents.
- Example :: "These 'interface artifacts' are an important part of the design of this skill and fundamentally how we spread complex work across many agents with different roles."
- Avoid :: hand-off (research's word), contract (harness-design's word, for a dependency)
- Specs :: skill-evals

* rubric
The written criteria for one kind of interface artifact that an eval agent scores an instance against, item by item.
- Example :: "we'll need to provide them with relevant rubricks they can record their evaluations against."
- Avoid :: checklist, criteria alone
- Specs :: skill-evals

* eval agent
An agent that examines an artifact a step produced and records an evaluation against a rubric; it takes no part in the cycle it evaluates.
- Example :: "eval agents will need to examine the artifacts."
- Avoid :: judge (the sources' word), Reviewer (a role of the skill)
- Specs :: skill-evals

* regression set
The fixed cases a skill change must pass before it is installed; expected to pass near 100% on the installed skill.
- Example :: its absence: "the cycles we use to evaluate a skill change are never the same."
- Avoid :: test suite, benchmark
- Specs :: skill-evals

* advisory set
Cases run beside the regression set whose result is reported and blocks nothing; where what is not yet reliable is measured.
- Example :: "gate the install with an advisory set alongside."
- Avoid :: soft gate, capability set (the sources' word)
- Specs :: skill-evals

* step
One piece of work one agent does between receiving its input and handing back.
- Example :: "many if not most or all of the steps taken by skill roles can be run with some kind of constructed mock input."
- Avoid :: phase (a phase holds many steps), task (a unit of the change's work)
- Specs :: skill-evals

* case
One eval: it names one outcome or one rule, the step where that is observed, the step's input, and the checks and rubric items applied to what the step wrote.
- Example :: the dispatcher's first step on a change whose cycle has closed, checked for a spawn of the plan phase agent.
- Avoid :: test (a product's), scenario (a spec's)
- Specs :: skill-evals

* trial
One run of a case. A case is run more than once because two runs of the same step on the same input differ.
- Example :: "let measured agreement set the trials."
- Avoid :: run alone (a replay is also run), attempt
- Specs :: skill-evals

* fixture
What a step needs besides its interface artifact in order to run: a checkout of the code at a commit for an Implementor or a Reviewer, a home with its record for a phase agent or the dispatcher.
- Example :: a clone of a home at the commit where a cycle closed.
- Avoid :: snapshot, stand-in (the testing skill's word, for a fake of a real thing), mock
- Specs :: skill-evals

* reference skill
The version of =orchestrate= a spec is extracted from: the current, working skill at a named commit, whose behaviour the spec first states. Agreed 2026-11-12 in the reopened research effort.
- Example :: "we are taking the current orchestration skill as a known working baseline to start from"
- Avoid :: baseline (=flows/execute.md='s word for the test run captured before merging), golden

* extraction record
The file, one per capability, in the research effort =research/skill-evals/extraction/= that shows where each statement backfilled into that capability's spec came from: the outcome ids, its provenance and its quotes from the reference skill. Frozen when the capability's spec is accepted; the spec never depends on it. Agreed 2026-11-12.
- Example :: =extraction/execute.org=, whose entry for "execute § Only merging stops" quotes =flows/execute.md= § 4 on both trees.
- Avoid :: basis, evidence (a research effort's agent files)

* gap
A behaviour a spec needs that the reference skill does not state: noted in the spec's =* Gaps= section, and never a requirement or scenario until the user decides it. Agreed 2026-11-12.
- Example :: what becomes of the merge that broke a test, while the user decides the regression ask.
- Avoid :: missing rule, TODO

* provenance
Whether a statement backfilled into a spec is =extracted= (the reference skill states it), =inferred= (our reading of it, reviewed by the user) or =filled= (a gap the user decided); recorded in the extraction record, not in the spec. Agreed 2026-11-12.
- Example :: "execute § A regression is recorded against its task" is =inferred=: the two trees record it differently.
- Avoid :: confidence
